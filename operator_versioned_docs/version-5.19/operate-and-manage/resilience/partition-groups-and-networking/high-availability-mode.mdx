High Availability mode avoids data loss when the Kubernetes node or availability zone is down. You can configure partition groups with High Availability mode to add resilience to your clusters.

Partition groups let you choose where Hazelcast members store backups of a data partition. You can configure a partition group to back up data to a member in a different availability zone (ZONE\_AWARE) or on a different Kubernetes node (NODE\_AWARE). See [Partition Group configuration](/hazelcast/latest/clusters/partition-group-configuration) for details.

When using either type of partition grouping (ZONE\_AWARE or NODE\_AWARE) with a Hazelcast cluster that spans multiple availability zones and nodes, you must have an equal number of members in each zone or node. Otherwise, distribution of partitions between members will be uneven.

The `highAvailabilityMode` parameter allows you to specify partition groups and to automatically distribute members across availability zones and nodes using the Kubernetes policy `topologySpreadConstraints`.

### Example configuration

The following example configures ZONE\_AWARE high availability.

```yaml
apiVersion: hazelcast.com/v1alpha1
kind: Hazelcast
metadata:
  name: hazelcast
spec:
  highAvailabilityMode: ZONE
```

## High Availability mode and multi-member routing

`MULTI_MEMBER` routing allows a client to connect to a subset of members that is determined by a grouping strategy. To benefit from `MULTI_MEMBER` routing, you must enable High Availability mode, because this parameter is used to determine partition groups. In addition, if the `MULTI_MEMBER` routing mode is used on the client side, `exposeExternally.type` must be set to `smart` in the Hazelcast CR.

Example server and client configuration using `MULTI_MEMBER` routing:

```yaml
apiVersion: hazelcast.com/v1alpha1
kind: Hazelcast
metadata:
  name: hazelcast
spec:
  highAvailabilityMode: ZONE
  exposeExternally:
    type: Smart
    discoveryServiceType: LoadBalancer
    memberAccess: LoadBalancer
```
