When an alert fires on a Hazelcast cluster member, it's important to gather as much data about the ailing member as possible in order to take suitable action. For this, you can use the following options.

## Hazelcast logs

You can collect Hazelcast logs from all members. If you run Hazelcast with a client-server topology, also collect client application logs before a restart. See the [Logging section](../operate-and-manage/maintaining-a-cluster/monitoring.mdx#logging) for details.

## Garbage collection logs

You can use `jstat` to retrieve garbage collection (GC) logs for a JVM as shown below:

```sh
jstat -gcutil -t JAVA_PID 1000 1
```

`JAVA_PID` is the ID of the Hazelcast process which you can find using, e.g. the `top` command.

You can also enable GC logging settings in your JVM options configuration. Below is an example configuration you can use as a starting point — you will define your own location, filecount, filesize etc.

```plain
-Xlog:gc*,gc+age=trace,safepoint:file=/path/to/gc.log:time,uptime,level,tags:filecount=10,filesize=10M
-XX:+HeapDumpOnOutOfMemoryError
-XX:HeapDumpPath=/path/to/heapdumps
```

:::note

This syntax uses the [Unified JVM Logging](https://openjdk.org/jeps/158) scheme which introduces a common logging system for all components of the JVM.

:::

These settings are explained in the table below:

| Parameter | Description |
| --- | --- |
| -Xlog:gc\* | Enables all GC logging at the default info level |
| gc+age=trace | Adds detailed information about object tenuring and aging |
| safepoint | Logs safepoint events related to application pauses |
| file=/path/to/gc.log | Specifies the log file location |
| time,uptime,level,tags | Includes timestamps, JVM uptime, log levels, and tags in log entries |
| filecount=10,filesize=10M | Sets up log rotation with 10 files of 10 MB each |
| -XX:+HeapDumpOnOutOfMemoryError | Generates a heap dump on OutOfMemoryError |
| -XX:HeapDumpPath=/path/to/heapdumps | Specifies the directory for heap dumps |

The JVM options configuration file (`jvm.options`) is located under the `config/` directory of your Hazelcast distribution. See the [Configuring JVM parameters section](../operate-and-manage/configuration/static-configuration/jvm-parameters.mdx) for more information on JVM configuration.

See the [GC Tuning guide](https://docs.oracle.com/javase/8/docs/technotes/guides/vm/gctuning/toc.html) by Oracle for more information about the garbage collection in JVMs.

## Thread dumps

Make sure you take thread dumps of the ailing member using either the Management Center (see the Monitoring Members sections of the Management Center documentation), `jstack`, tools such as visualVM, or a script. Take multiple snapshots of thread dumps at 3–4 second intervals.

### Use a script to generate a Java thread dump

1. Note the process ID number of the Java process (`JAVA_PID`), e.g. using `top`.
2. Prepare a shell script with the content as shown below; name the script as `threaddump.sh`:

   ```none
    #!/bin/sh #
   # Takes the Target Java Process PID as an argument. #
   # Create thread dumps a specified number of times and INTERVAL. Thread dumps
   # will be in the file where stdout was redirected or in console output. #
   # Usage: sh ./threaddump.sh #
   # Number of times to collect data.
   LOOP=6
   # Interval in seconds between data points. INTERVAL=20
     for ((i=1; i <= $LOOP; i++))
     do
   kill -3 $1
   echo "thread dump #" $i if [ $i -lt $LOOP ]; then
   echo "Sleeping..."
           sleep $INTERVAL
        fi
   done
   ```
3. Make the script executable using `chmod 755`. This example script captures a series of 6 thread dumps spaced 20 seconds apart (modify as needed), passing in the Java process ID as an argument.
4. Kill the process using the `kill -QUIT` or `kill -3` command:

   ```none
   kill -3 JAVA_PID
   ```
5. Run the script as follows:

   ```none
   sh ./threaddump.sh JAVA_PID
   ```

Be sure to test the script before the issue happens to make sure it runs properly in your environment.

### Use jstack to generate thread dumps

You can also use `jstack` to generate thread dumps if you run Hazelcast on OpenJDK, or Sun JDK 1.6 or newer (just be sure that your JVM configuration does not include the `-Xrs` parameter):

1. Note the process ID number of the Java process (`JAVA_PID`), e.g. using `top`.
2. Kill the process using the `kill -QUIT` or `kill -3` command:

   ```none
   kill -3 JAVA_PID
   ```
3. Run the following command to write the thread dump to the `jstack.out` file:

   ```none
   jstack -l JAVA_PID > jstack.out
   ```

Alternatively, you can always use the following tools to generate thread dumps:

- [JConsole](http://openjdk.java.net/tools/svc/jconsole/)
- [VisualVM](https://visualvm.github.io/)
- [GlowRoot](https://github.com/glowroot/glowroot)
- [YourKit](http://www.yourkit.com/)
- [JProfiler](http://www.ej-technologies.com/products/jprofiler/overview.html)

## Heap dumps

Make sure you take heap dumps and histograms of the ailing JVM. For this, you can use the JDK's `jmap` tool:

1. Note the process ID number of the Java process (`JAVA_PID`), e.g. using `top`.
2. Run the following command:

   ```none
   jmap -dump:live,file=<file-path> JAVA_PID
   ```

   `file=file-path` specifies the name and path of the file where heap dump will be written.

:::tip

For more options for capturing a heap dump using JDK tools or the JRE, see this [Baeldung tutorial](https://www.baeldung.com/java-heap-dump-capture).

:::

You can also create and run a script. For example:

```plain
if [ "x$MIN_HEAP_SIZE" != "x" ]; then
JAVA_OPTS="$JAVA_OPTS -Xms${MIN_HEAP_SIZE}"

fi
if [ "x$MAX_HEAP_SIZE" != "x" ]; then
JAVA_OPTS="$JAVA_OPTS -Xmx${MAX_HEAP_SIZE}"
fi

JAVA_OPTS="$JAVA_OPTS -XX:+UseG1GC -XX:+UseCompressedOops -XX:+UseGCLogFileRotation -XX:NumberOfGCLogFiles=10 -XX:GCLogFileSize=20M -XX:+PrintGCDetails -XX:+PrintGCDateStamps -Xloggc:/path/to/your/log/directory/hazelcast-gc.log.`date +%Y- %m-%d-%H-%M` -XX:+HeapDumpOnOutOfMemoryError -XX:HeapDumpPath=/path/to/your/log/directory/ -verbose:gc -Dlog4j.configuration=file:/path/to/your/log/directory/log4j.properties -Djava.security.egd=file:/dev/./urandom -Djava.io.tmpdir=/path/to/your/tmp/directory/tmp/"
```
