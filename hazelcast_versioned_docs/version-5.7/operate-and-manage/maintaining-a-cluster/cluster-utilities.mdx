Hazelcast Platform is provided with a range of programmatic utilities that you can use to manage your Hazelcast clusters, including command line interfaces and scripts.

These utilities are included in the `bin` directory in your Hazelcast package and are designed for Unix-like systems. Utilities with a `.bat` version are compatible with Microsoft Windows.

`bin` contains the following files.

| Filename | Description |
| --- | --- |
| `hz` | Starts a Hazelcast member with customizable configuration.|
| `hz-cli`, `hz-cli.bat` | Manages jobs and snapshots on a running cluster. Also used to launch the Hazelcast console and SQL shell. |
| `hz-cluster-admin` | Performs cluster lifecycle operations, such as force starts and upgrades. |
| `hz-cluster-cp-admin` | Manages the CP Subsystem. See [Manage and monitor the CP subsystem](../cp-subsystem/management.mdx). |
| `hz-healthcheck` | Retrieves cluster state from the HTTP health check endpoint. See [Using the health check script](../monitoring/health-check-and-monitoring.mdx#health-check-script). |
| `hz-start`, `hz-start.bat` | Starts a Hazelcast member with the default settings. Where possible, use `hz start` instead. |
| `hz-stop`, `hz-stop.bat` | Stops all running Hazelcast members on the local device. `hz-stop` sends `SIGTERM`, and by default the member terminates without a graceful shutdown. To shut down gracefully, set the `hazelcast.shutdownhook.policy` property to `GRACEFUL`. `hz-stop.bat` always stops the member without a graceful shutdown. |
| `common.bat`, `common.sh` | Shared code called by other scripts. You should not run this directly. |

:::note

Hazelcast also provides a suite of products for managing and monitoring your Hazelcast deployment. For more information, see the following:

- <Variable href="/management-center/{page-latest-supported-mc}/getting-started/overview" text="Management Center" />
- <Variable href="/operator/{page-latest-supported-po}/" text="Platform Operator"/>
- <Variable href="/clc/{page-latest-supported-clc}/overview" text="Command Line Client (CLC)" />

:::

## `hz` command line interface {/* #hz */}

The `hz` CLI allows you to start a Hazelcast instance from the shell. The CLI automates the steps required to install and start the software and supports several options to override the default settings.

To create and start a Hazelcast member:

1. Navigate to the `bin` directory in your Hazelcast package
2. Start the software using the default settings or a custom configuration

To start the software with the default settings:

```bash
./hz start
```
Alternatively, add an option to override the default configuration. For example, to specify a port number:

```bash
./hz start -p 5705
```

To specify a custom configuration file:

```bash
./hz start -c path/to/file.xml
```

### `hz` options

The `hz` command has one subcommand, `start`, which starts a member. On its own, `hz` takes `-h` or `--help` to print its help, and `-V` or `--version` to print the Hazelcast version.

The `hz start` command takes the following options:

| Option | Description |
| --- | --- |
| `-c`, `--config <file>` | Uses `<file>` as the member configuration. The file can be XML or YAML. |
| `-p`, `--port <port>` | Binds the member to `<port>`. If the port is in use, the member uses the next free port. The default is `5701`. |
| `-i`, `--interface <interface>` | Binds the member to `<interface>` only. |
| `-h`, `--help` | Prints the help for `hz start`. |

To stop a member after using `hz start`, exit the terminal with <kbd>Ctrl</kbd>+<kbd>C</kbd>. By default, the member terminates without a graceful shutdown. For a graceful shutdown, set the `hazelcast.shutdownhook.policy` property to `GRACEFUL`.

For a tutorial showing how to start a cluster with this tool, see [Start a Local Cluster with the CLI](../../get-started/start-a-local-cluster/get-started-cli.mdx).

## `hz-cli` command line interface {/* #hz-cli */}

:::tip

Consider using the Hazelcast <Variable href="/clc/{page-latest-supported-clc}/overview" text="Command Line Client (CLC)" /> instead, as it has more features.

:::

The `hz-cli` tool has a range of uses:

- [Managing Jet streaming jobs](../../develop-and-build/building-data-pipelines/job-management.mdx) and job snapshots.
- Launching the [SQL shell](../../develop-and-build/sql/sql-overview.mdx), which you can use to run SQL queries.
- Launching the [Hazelcast console](../../get-started/start-a-local-cluster/get-started-cli.mdx#step-4-write-data-to-memory), which you can use to write data to a map for testing and evaluation (not recommended for production).

### `hz-cli` options

The `hz-cli` command takes one of the following subcommands:

| Subcommand | Description |
| --- | --- |
| `sql` | Starts the SQL shell. |
| `console` | Starts the Hazelcast console. |
| `submit <jar file> [<arguments>]` | Submits the job in `<jar file>` to the cluster, and passes `<arguments>` to it. Options: `-n`, `--name <name>` sets the job name. `-c`, `--class <class>` sets the fully qualified name of the main class in the JAR file. `-s`, `--snapshot <snapshot name>` starts the job from the named snapshot. |
| `list-jobs` | Lists the running jobs. Options: `-a`, `--all` also lists completed and failed jobs. |
| `suspend <job name or id>` | Suspends a running job. |
| `resume <job name or id>` | Resumes a suspended job. |
| `restart <job name or id>` | Restarts a running job. |
| `cancel <job name or id>` | Cancels a running job. |
| `save-snapshot <job name or id> <snapshot name>` | Exports a named snapshot of a job. Options: `-C`, `--cancel` cancels the job after the snapshot. |
| `list-snapshots` | Lists the exported snapshots. Options: `-F`, `--full-job-name` shows job names in full. |
| `delete-snapshot <snapshot name>` | Deletes a named snapshot. |
| `cluster` | Shows the cluster state and information about the members. |
| `help <subcommand>` | Prints the help for `<subcommand>`. |

The `hz-cli` command and every subcommand take the following options:

| Option | Description |
| --- | --- |
| `-t`, `--targets [<cluster-name>@]<hostname>:<port>[,<hostname>:<port>]` | Connects to the given cluster instead of the one in the client configuration file. At least one address is required. The cluster name is optional. |
| `-v`, `--verbosity` | Shows verbose logs and the full stack trace of errors. |
| `--ignore-version-mismatch` | Connects even if the client and member minor versions differ. |

The `hz-cli` command also takes the following options before the subcommand:

| Option | Description |
| --- | --- |
| `-f`, `--config <file>` | Uses `<file>` as the client configuration. The file can be XML or YAML. The default is `config/hazelcast-client.xml`. |
| `-h`, `--help` | Prints the help for `hz-cli`. |
| `-V`, `--version` | Prints the Hazelcast version. |

For a tutorial showing how to start a cluster and run the SQL shell, see [Start a Local Cluster from Binary](../../get-started/start-a-local-cluster/get-started-binary.mdx).

## `hz-cluster-admin` script {/* #using-the-hz-cluster-admin-script */}

You can use the script `hz-cluster-admin` to perform cluster lifecycle operations such as changing state, changing the cluster version, or shutting down the cluster.

The script calls the [Community Edition REST API](../../clients-and-apis/apis/enterprise-rest-api/rest-api.mdx). To call the same endpoints without the script, see [Managing Cluster's State](../../clients-and-apis/apis/enterprise-rest-api/rest-api.mdx#managing-clusters-state). You can also perform these operations in Management Center, where force start and partial start are on the **Persistence** tab. See <Variable href="/management-center/{page-latest-supported-mc}/clusters/persistence" text="Persistence" />.

:::caution[Deprecation Notice for the Community Edition REST API]

The [Community Edition REST API](../../clients-and-apis/apis/enterprise-rest-api/rest-api.mdx) has been deprecated and will be removed as of Hazelcast version 7.0. An improved Enterprise version of this feature is available and actively being developed. For more information, see [Enterprise REST API](../../clients-and-apis/apis/enterprise-rest-api/overview.mdx).

:::

To use `hz-cluster-admin`:
- Ensure the `curl` command is available in your environment.
- Enable the [Community Edition REST API](../../clients-and-apis/apis/enterprise-rest-api/rest-api.mdx), and the endpoint group for each operation you use: `CLUSTER_READ` for `get-state` and `get-cluster-version`, `CLUSTER_WRITE` for `change-state`, `shutdown`, and `change-cluster-version`, and `PERSISTENCE` for `force-start` and `partial-start`. Only `CLUSTER_READ` is enabled by default.

### `hz-cluster-admin` options

If you do not set a parameter, the script uses its default value. The `hz-cluster-admin` script takes the following parameters:

| Parameter | Default Value | Description |
| --- | --- | --- |
| `-o` or `--operation` | `get-state` | Executes a cluster-wide operation. The <Variable name="open-source-product-name" /> operations are `get-state`, `change-state`, `shutdown`, and `get-cluster-version`. The <Variable name="enterprise-product-name" /> operations are `force-start`, `partial-start`, and `change-cluster-version`. For `force-start`, see [Triggering a Force-Start](../fault-tolerance/persistence/triggering-force-start.mdx). |
| `-s` or `--state` | None | Updates the state of the cluster to a new state. New state can be `active`, `no_migration`, `frozen`, `passive`. This is used with the operation `change-state`. This parameter has no default value; when you use this, you should provide a valid state. |
| `-a` or `--address` | `127.0.0.1` | Defines the IP address of a cluster member. If you want to manage your cluster remotely, you should use this parameter to provide the IP address of a member to this script. |
| `-p` or `--port` | `5701` | Defines on which port Hazelcast is running on the local or remote machine. |
| `-c` or `--clustername` | `dev` | Defines the name of a cluster which is used for a simple authentication. When security is enabled, the member uses this value as the username. See the [Creating Clusters section](../partition-groups-and-networking/creating-clusters.mdx). |
| `-P` or `--password` | `dev-pass` | Defines the password of a cluster. The member checks the password only when security is enabled. |
| `-v` or `--version` | None | Defines the cluster version to change to. It is used in conjunction with the `change-cluster-version` operation. |
| `-d` or `--debug` | Off | Prints verbose output from `curl`. |
| `-h` or `--help` | None | Prints the help for `hz-cluster-admin`. It must be the first parameter. |
| `--https` | Off | Enables HTTPS for REST calls between `hz-cluster-admin` and the cluster. Applicable when TLS is enabled on the cluster. |
| `--cacert` | The CA certificates that `curl` trusts by default | Defines trusted PEM-encoded certificate file path to verify member certificates. Applicable when TLS is enabled on the cluster. |
| `--cert` | None | Defines PEM-encoded client certificate file path. Applicable when TLS is enabled on the cluster. |
| `--key` | None | Defines PEM-encoded client private key file path. Applicable when TLS is enabled on the cluster. |
| `--insecure` | Off | Disables member certificate verification. Applicable when TLS is enabled on the cluster. |

### Examples {/* #using-hz-cluster-admin */}

In the following examples, a cluster named `test` runs on remote machines, and one member has the IP address `172.16.254.1` and port `5702`. Run the commands from the `bin` directory:

| Task | Command |
| --- | --- |
| Get the cluster state | `./hz-cluster-admin -o get-state -a 172.16.254.1 -p 5702 -c test` |
| Change the cluster state to `frozen` | `./hz-cluster-admin -o change-state -s frozen -a 172.16.254.1 -p 5702 -c test` |
| Shut down the cluster | `./hz-cluster-admin -o shutdown -a 172.16.254.1 -p 5702 -c test` |
| Trigger a partial start (persistence enabled) | `./hz-cluster-admin -o partial-start -a 172.16.254.1 -p 5702 -c test` |
| Trigger a force start (persistence enabled) | `./hz-cluster-admin -o force-start -a 172.16.254.1 -p 5702 -c test` |
| Get the cluster version | `./hz-cluster-admin -o get-cluster-version -a 172.16.254.1 -p 5702 -c test` |
| Change the cluster version to `X.Y` | `./hz-cluster-admin -o change-cluster-version -v X.Y -a 172.16.254.1 -p 5702 -c test` |

The cluster version is in the `major.minor` format, for example 3.12. The member also accepts a patch version or suffix, such as 3.12.1, but uses only the major and minor numbers. Other formats result in a failure. To learn when to change the cluster version, see [Rolling Upgrades](../../install-and-upgrade/upgrade/rolling-upgrades.mdx).

When the members use TLS, add `--https`:

```sh
./hz-cluster-admin --https \
  --operation get-state --address member1.example.com --port 5701
```

If your certificate authority is not in the default trusted set, for example with a self-signed certificate, set `--cacert` to a file that contains the root certificates:

```sh
./hz-cluster-admin --https \
  --cacert /path/to/ca-certs.pem \
  --operation get-state --address member1.example.com --port 5701
```

When TLS mutual authentication is enabled, also set the client certificate and its private key:

```sh
./hz-cluster-admin --https \
  --key privkey.pem \
  --cert cert.pem \
  --operation get-state --address member1.example.com --port 5701
```

## Integrity checker

The integrity checker is a utility developed for Java developers who build Hazelcast applications. It checks the classpath of your applications built with Hazelcast JAR dependencies (e.g., `hazelcast` or `hazelcast-sql`, using the assembly or other uber-JAR plugins). This check involves the verification of all serializer hooks are loaded during a Hazelcast member startup, that is, it verifies that the executable of your application contains all the required `META-INF/services` files.

For example, there may be cases where:
- You add a new `DataSerializer` hook for your application, but do not update the corresponding `/META-INF/services/com.hazelcast.DataSerializerHook` file
- You build an application with a plugin that merges dependency JARs into the application's executable JAR; the plugin might be misconfigured and `DataSerializerHook` files are not merged correctly, resulting in a corrupted executable

The integrity checker is disabled by default, and can be used for development clusters on your local machines. It is not recommended for production clusters, where the integrity of applications are already verified, because it is a compute-intensive check.

Enable it in the configuration as follows:

<Tabs groupId="environment-variable--java-member-api--system-prop--xml--yaml">
<TabItem value="yaml" label="YAML">

```yaml
hazelcast:
  integrity-checker:
    enabled: true
```

</TabItem>
<TabItem value="xml" label="XML">

```xml
<hazelcast>
    <integrity-checker enabled="true"/>
</hazelcast>
```

</TabItem>
<TabItem value="java-member-api" label="Java member API">

```java
Config config = new Config();
config.getIntegrityCheckerConfig().setEnabled(true);

HazelcastInstance hazelcast = Hazelcast.newHazelcastInstance(config);
```

</TabItem>
<TabItem value="system-prop" label="System Prop">

```shell
-Dhz.integritychecker.enabled=true
```

</TabItem>
<TabItem value="environment-variable" label="Environment Variable">

```shell
HZ_INTEGRITYCHECKER_ENABLED=true
```

</TabItem>
</Tabs>

If the verification fails, the member does not start and the checker prints which hook is missing its corresponding `/META-INF/services/com.hazelcast.DataSerializerHook`. Example log output:

```shell vars
SEVERE: [192.168.56.1]:5701 [dev] [{full-version}] Node creation failed
com.hazelcast.core.HazelcastException: Failed to verify distribution integrity, unable to load DataSerializerHook: com.hazelcast.aggregation.impl.AggregatorDataSerializerHook
```
